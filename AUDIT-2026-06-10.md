# RuneWise Improvement Roadmap

*Synthesized from an 18-auditor deep audit of v2.0.3 (main, clean).*

---

## 1. Executive Summary

RuneWise's bones are genuinely good — the lazy view registry, the `fetchJson` cache/dedupe/stale-fallback layer, DOMPurify-gated HTML injection, pure unit-tested formula modules, and the dark theme are all the right shape and should not be churned. The problem is a credibility gap between what the app promises and what it computes: the numbers players act on are systematically wrong (GE tax is absent from every gp surface, raid EV is 7–12x inflated, the recent DPS "fix" in 6ca994f zeroed real spec multipliers), the notification system is theater (every alert dies when its view unmounts or the window hides to tray — the app's flagship close-to-tray behavior), and a cluster of features work in `vite dev` but are broken in the shipped Tauri build (onboarding validation, Clear Cache, 16 files of dead external links). None of this requires architectural change — it's adoption of abstractions that already exist, plus correctness passes that are mostly S/M effort.

## 3. Fix Now — Confirmed Critical/High Bugs

### A. Money math (one shared helper fixes the family)

The root cause is identical everywhere: gp arithmetic reimplemented per surface, zero occurrences of "tax" in `src/`.

- **Create `src/lib/tax.ts`**: `geTax(price) = price < 50 ? 0 : Math.min(Math.floor(price * 0.02), 5_000_000)`, plus a `netMargin(high, low)` helper.
- **Flip journal** (`FlipJournal.tsx:23-25`): profit = `(sellPrice - geTax(sellPrice) - buyPrice) * qty`. Export `calcProfit` so the existing test stops asserting a re-implemented copy (`power-features.test.ts:94-97`).
- **Market margins** (`shared.ts:110-111`, `Market.tsx:440-443, 706-709`, `BulkSearch.tsx:94-97`, `ShopHelper.tsx:331`): route through `netMargin`, relabel "Margin (after tax)".
- **Market alch column** (`Market.tsx:710-713`): subtract nature rune price (`prices["561"]?.high ?? 250`) so it stops contradicting the Alch tab one click away (`AlchCalculator.tsx:45,59`).
- **Production/recipes/farm profit** (`ProductionCalc.tsx:67-74`, `RecipeCostTable.tsx:59-64`, `WikiRecipeTable.tsx:59-61`, `FarmProfit.tsx:33-39`): apply `geTax` to output values.
- **Raid loot EV** (`RaidLootCalc.tsx:44-52`, confirmed): compute `P(unique) = 1/dropRate` once, distribute across items by wiki weights, row EV = `P × weight × price`. Derive the static `rateDescription` strings from the same function so `Raids.tsx:227` and the calculator agree.
- **Loot rarity parsing** (`Loot.tsx:80-87`): generalize the `1/x`-only regex so `3/128` and `2 × 1/128` stop silently contributing 0 or half EV.

### B. DPS engine, round 2 (6ca994f regression + open holes)

The skeleton (effective level / rolls / hit chance, tbow curve, claws cascade) is correct — don't churn it. Fix the values and the magic path:

- **Spec multipliers** (`spec-weapons.ts:50,62,98`): DWH 1.5, BGS 1.21, Ancient GS 1.1. Update the pinning tests with wiki-cited values — they currently enshrine the regression.
- **Modifier table** (`dps.ts:84-168`): salve (ei) magic is +20% not the salve (i) 15% that 6ca994f applied; leaf-bladed battleaxe has no accuracy bonus; tbow magic clamp is 350 in CoX.
- **Mutual exclusivity** (`useDpsState.ts:583-593`): add exclusivity groups — {slayer_helm, salve_e, salve_ei} and per-style {void, elite_void}. Currently stacks 7/6 × 1.2.
- **Monster magic defence** (`dps.ts:335-337`): use the NPC formula (Magic level, +9 already added by defenseRoll), not the player 70/30 blend.
- **ToA scaling** (`dps.ts:443-451`): HP × (1 + 0.004 × raidLevel); delete the defence scale entirely (ToA doesn't scale defence).
- **Tumeken's shadow** (`dps.ts:302-305`): cap tripled magic damage at +100%; 4x inside ToA.
- **No-spell magic fallback** (`dps.ts:276,309-311`): default to a powered-staff/spell selection instead of running the melee max-hit formula on magic damage %.
- **Weapon attack speed** (`equipment.ts:132`): static name→ticks lookup (or scrape the infobox); apply `stance.speedMod` to the manual fallback too; stamp speed into presets. Unblocks the dead code at `useDpsState.ts:345-348` and `StatsPanel.tsx:240`, plus a Gear Compare speed column.
- **Scythe + fang** (`dps.ts:280-344`): add bespoke handling mirroring the tumekens_shadow special case (scythe 3-roll, fang `1-(1-acc)²`). This is the L-effort item — last in the queue but it's the flagship-weapon credibility gap.
- **Loadout bugs** (`useDpsState.ts:305,484`): cross-style apply drops gear (mirror lines 632-633 in the pendingLoadout branch); comparison resolves stances from GENERIC_STANCES and uses stale manual speed.

### C. Notifications & background behavior

One structural fix kills five findings: alerts live in view-scoped effects gated on `visibilityState === "visible"` — guaranteed never to fire in the app's headline tray-resident mode.

- **Mount a headless `AlertsManager` in App.tsx** owning the watchlist poll, farm-timer ready check, and star poll. Drop the visibility gates (`useWatchlist.ts:31`, `FarmTimers.tsx:252`).
- **Lift watchlist into a context provider** (like GEDataProvider) — fixes the dual-instance threshold-wipe (`Market.tsx:289` + `Watchlist.tsx:62` over one localStorage key) for free.
- **De-burst notifications**: persist notified milestone keys per RSN (`XpTracker.tsx:393,447` re-fires the player's entire achievement history per mount); seed star seen-keys on first fetch without notifying (`ShootingStars.tsx:299-320`); repeat farm timers jump `readyAt` forward in one step instead of one notification per missed cycle (`FarmTimers.tsx:258-280`).
- **Windows parity**: add `tauri-plugin-single-instance` as the first plugin (close-to-tray is a second-instance trap on Windows, `lib.rs:349`); gate `NSUserNotificationDefaultSoundName` on `isMac` (`notify.ts:130` silences Windows toasts entirely).

## Appendix B — All Findings by Severity

### Critical (8)

**Flip journal tax math wrong on both rate and base — profits badly overstated** ✅ (hand-verified)  
`src/features/flip-journal/FlipJournal.tsx:25` · bug · effort S · src: calculators  
calcProfit returns floor((sell - buy) * qty * 0.99): it applies 1% (GE tax has been 2% since May 2025) and applies it to the margin instead of the sell price. Real profit is (sell - floor(sell*0.02) - buy) * qty, so e.g. buy 950 / sell 1000 / qty 1000 shows 49.5k when the true figure is 30k — a 65% overstatement on exactly the thin-margin flips this journal exists for. The same wrong formula is duplicated inline in CloseModal (FlipJournal.tsx:405,407), and sub-50gp/exempt items (which pay no tax) are over-taxed.  
*Fix:* Add a shared geTax(sellPrice) helper (floor(price*0.02) per item, 0 below 50 gp, exemption list) in src/lib/, compute profit as (sell - geTax(sell) - buy) * qty, and use it in both calcProfit and CloseModal.
